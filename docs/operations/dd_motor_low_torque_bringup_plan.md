# DD Motor Low Torque Bring-up Plan

## 目的

教育用可変型定力装置の本線候補であるモータドライバ内蔵DDモータ（RobStride EDULITE 05, DDT-M0602C234）を、安全かつ段階的に立ち上げる（Bring-up）ための手順と判断基準を定義する。

## Bring-up フェーズ

> [!NOTE]
> **適用範囲に関する注意**
>
> 初期bring-upでは、対象モータの仕様上もっとも安全に扱える制御モードとして、速度モードを使う場合がある。
> ただし、速度モードでのbring-upに成功したことは、そのモータが定力制御に適していることを意味しない。
>
> 定力装置の本線候補として評価するには、後続工程で次を確認する必要がある。
>
> - トルク指令の有無
> - 電流指令の有無
> - telemetryの意味と単位
> - 低速・低トルク域での線形性
> - 発熱および電流制限

### Phase 1: 通信確認
- モータの電源を入れ、DinMeterと通信（CANまたはRS485）が確立できるか確認する。
- 制御コマンド（Enable等）は一切送信しない。

### Phase 2: Telemetry取得確認
- モータを停止（Disabled）状態に保ったまま、必要に応じて治具や安全なつまみ等で軸を低速に動かし、位置や速度、バス電圧などのTelemetryが正しく受信・解釈できるか確認する。

### Phase 3: 最小指令送信（無負荷）
- `Armed` 状態へ移行し、安全限界を極めて低く設定した上で、最小の速度指令またはトルク指令を送信する。
- 指令に対してモータが予期した方向に回転することを確認する。

### Phase 4: CSV記録
- 動作中のTelemetryとシステム状態が、`dd_motor_csv_logging_plan.md` で定義されたスキーマ通りにCSVとして記録できるか確認する。

### Phase 5: データ転送
- 記録したCSVデータをQRコードまたはローカルPCへ転送し、後段のアプリでパース可能か確認する。

### Phase 6: 指令値-応答確認（無負荷）
- 複数の速度/トルク指令を与え、Telemetryとして返ってくる応答値が物理的に妥当であるか確認する。

### Phase 7: 線形性確認（小負荷）
- モータに既知ばね・重り・治具など、身体を巻き込まない既知負荷をかけ、指令値とTelemetryの応答（相電流やトルク推定値）に線形性があるか確認する。

### Phase 8: 安全停止条件の確認
- 通信切断（タイムアウト）、過負荷、状態異常（Faultフラグ）が発生した際、DinMeter側が確実に `Fault` 状態へ遷移し、モータを安全に停止・無効化（Disabled）できるか確認する。

## Go / NoGO 条件

### GO（成功・継続条件）
以下のすべてを満たす場合、本採用へ向けた開発を継続する。

- CAN/RS485によるTelemetryが安定して取得できる。
- 指令値と応答値の関係を論理的に説明できる。
- 低速・低トルク領域で安定動作する（ガタつきや極端な振動がない）。
- CSVに意味（Semantics）付きのデータが正常に記録される。
- 通信異常時等の安全停止条件を明確に設計・実装できる。
- 教室で扱える電源仕様・サイズ・運用負荷に収まっている。

### NoGO（不採用・見直し条件）
以下のいずれかに該当する場合、対象ハードウェアの採用を見直す。

- トルク指令（または速度指令）と応答の因果関係が説明できない。
- Telemetryが取得できない、またはノイズが多すぎて使い物にならない。
- 低速域での動作が不安定である。
- 連続稼働時の発熱が教室運用において危険なレベルである。
- 安全停止（キルスイッチ・通信断検知）が確実に機能しない。
- データをCSVで記録・抽出する手段がない。
- **unknown（不明）な測定値を、教材判断や授業の考察に使う必要がある。**

## 撤退条件（Withdrawal Conditions）
万が一、DDモータによる制御でも「低トルク域での安全な制御が困難」「Telemetryの精度が教育用に不適」「通信プロトコルが不安定でFaultが頻発する」といった根本的な問題が解決できない場合、直ちに実機運用から撤退し、アーキテクチャの再選定を行う。
